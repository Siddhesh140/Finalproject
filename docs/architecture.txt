                         1. PROJECT OVERVIEW
================================================================================

Video-RAG is a full-stack AI-powered video learning platform that:
  - Processes videos from YouTube URLs or file uploads
  - Transcribes audio using AI (Whisper)
  - Enables RAG-powered chat (ask questions about videos)
  - Generates quizzes from video content
  - Provides semantic search across all videos

                      5. BACKEND TECHNOLOGIES
================================================================================

FASTAPI
-------
What: Modern, fast Python web framework
Why:  Async support, auto docs, type validation
Use:  Building REST API endpoints

Features:
  - Async/await for non-blocking I/O
  - Automatic Swagger docs at /docs
  - Pydantic integration for validation

Example:
  @app.post("/videos")
  async def create_video(video: VideoCreate):
      return {"id": "123", **video.dict()}

--------------------------------------------------------------------------------

SQLALCHEMY
----------
What: Python ORM (Object-Relational Mapper)
Why:  Write Python instead of SQL, database agnostic
Use:  All database operations (CRUD)

Example:
  class Video(Base):
      __tablename__ = "videos"
      id = Column(String, primary_key=True)
      title = Column(String)

  # Query
  video = db.query(Video).filter(Video.id == "123").first()

--------------------------------------------------------------------------------

PYDANTIC
--------
What: Data validation using Python type hints
Why:  Automatic validation, clear errors
Use:  Request/response validation, settings

Example:
  class VideoCreate(BaseModel):
      url: str
      title: str

  # Automatic validation on API requests

--------------------------------------------------------------------------------

UVICORN
-------
What: ASGI server for Python async apps
Why:  Production-ready, HTTP/2 support
Use:  Running FastAPI application

Command:
  uvicorn app.main:app --reload --port 8000

--------
What: Vector database for AI applications
Why:  Semantic similarity search, persistent storage
Use:  Storing embeddings, RAG retrieval

  2. Store vectors in ChromaDB
  3. Query: Convert question to vector

                     9. KEY CONCEPTS EXPLAINED
================================================================================

RAG (RETRIEVAL AUGMENTED GENERATION)
------------------------------------
Problem: LLMs don't know about YOUR specific videos
Solution: Combine retrieval with generation

  1. CHUNK    - Split transcript into ~500 word pieces
  2. EMBED    - Convert each chunk to 768-dimension vector
  3. STORE    - Save vectors in ChromaDB
  4. RETRIEVE - Find chunks similar to user's question
  5. GENERATE - Send question + relevant chunks to LLM

  +------------------------------------------------------------------+
  |                    RAG Pipeline                                   |
  |                                                                   |
  |  [Question] --> [Vectorize] --> [Search ChromaDB]                |
  |                                        |                          |
  |                                        v                          |
  |                              [Relevant Chunks]                    |
  |                                        |                          |
  |                                        v                          |
  |                     [LLM Prompt: Context + Question]             |
  |                                        |                          |
  |                                        v                          |
  |                            [AI-Generated Answer]                  |
  +------------------------------------------------------------------+

--------------------------------------------------------------------------------

VECTOR EMBEDDINGS
-----------------
What: Numerical representations of text (768 numbers)
Why:  Similar meanings = similar vectors

  "The cat sat on the mat"  -->  [0.2, 0.8, -0.3, 0.1, ...]
  "A kitten was on the rug" -->  [0.25, 0.75, -0.28, 0.15, ...]  (Similar!)
  "Python is a language"    -->  [0.9, -0.5, 0.2, 0.7, ...]      (Different!)

--------------------------------------------------------------------------------

ORM (OBJECT-RELATIONAL MAPPING)
-------------------------------
What: Technique to use objects instead of SQL
Why:  Easier, safer, database-agnostic

  Without ORM:
    cursor.execute("SELECT * FROM videos WHERE id = ?", (id,))
    row = cursor.fetchone()
    title = row[1]

  With ORM (SQLAlchemy):
    video = db.query(Video).filter(Video.id == id).first()
    title = video.title

--------------------------------------------------------------------------------

REST API
--------
What: Architectural style for web services
Why:  Standard, stateless, scalable

  Your API:
    GET    /api/videos        - List all videos
    POST   /api/videos        - Create video
    GET    /api/videos/{id}   - Get single video
    DELETE /api/videos/{id}   - Delete video
    POST   /api/chat          - Send message to AI
    POST   /api/quiz/generate - Create quiz

--------------------------------------------------------------------------------

REST API vs FASTAPI - KEY DIFFERENCE
-------------------------------------
These are NOT alternatives - they work together!

  REST API = The PATTERN (set of rules/guidelines)
  FastAPI  = The TOOL (Python framework that follows the pattern)

Analogy:
  REST    = Recipe (rules for how a dish should be made)
  FastAPI = Chef (who follows the recipe to cook)

+------------------------------------------------------------------+
|                         REST API                                  |
|                    (Design Pattern/Rules)                         |
|                                                                   |
|   Rules:                                                          |
|   - Use HTTP methods (GET, POST, PUT, DELETE)                    |
|   - Resources identified by URLs (/api/videos)                   |
|   - Stateless communication                                       |
|   - Return JSON responses                                         |
+------------------------------------------------------------------+
                              |
                              | Implemented by
                              v
+------------------------------------------------------------------+
|                         FastAPI                                   |
|                    (Python Framework)                             |
|                                                                   |
|   - Something you install: pip install fastapi                   |
|   - Actual Python code you write                                 |
|   - Automatically follows REST principles                        |
|   - Adds features: async, validation, auto-docs                  |
+------------------------------------------------------------------+

Comparison:
+---------------+---------------------------+---------------------------+
| Aspect        | REST API                  | FastAPI                   |
+---------------+---------------------------+---------------------------+
| What is it?   | Architecture pattern      | Python framework          |
| Install?      | No (just guidelines)      | Yes (pip install)         |
| Language      | Language-agnostic         | Python only               |
| You write     | Nothing (it's a concept)  | Actual code               |
+---------------+---------------------------+---------------------------+

Other frameworks that also implement REST:
  - Flask (Python)
  - Express (JavaScript)
  - Django REST Framework (Python)
  - Spring Boot (Java)

Why FastAPI for REST?
  1. Async support (handles slow AI calls efficiently)
  2. Automatic Swagger docs at /docs
  3. Built-in validation with Pydantic
  4. Fastest Python REST framework
